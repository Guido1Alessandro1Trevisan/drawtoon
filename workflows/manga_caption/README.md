# Drawtoon Manga Panel Caption

Haiku-only panel caption workflow.

Input:

```text
s3://drawtoon/datasets/pages/filtered/<chapter>/<page_side>.jpg
s3://drawtoon/datasets/annotations/magi_v3/<chapter>/<page_side>.jsonl
```

Output:

```text
s3://drawtoon/captions/<caption_run>/<chapter>/<page_side>.json
```

Each page worker sends one Bedrock request per panel and stores one page JSON with embedded panel captions. Haiku returns only the caption body. The worker injects the manga prefix afterward so stored captions start like:

```text
Black and White Manga. 20th Century Boys by Naoki Urasawa. Character 1 ...
```

The prompt references only `Character N` labels, not visual feature descriptions. It asks Haiku for a 30-80 word FLUX-style caption body ordered around visible subject/action, setting/background, shot size or camera angle, and useful visual effects. Captions should stay descriptive, not interpretive.

Haiku also classifies each text region as exactly one of:

```text
Speech Bubble
Narration Bubble
Shout Bubble
```

Boxes stay deterministic from MAGI-v3 annotations and are not generated by the model. Training layout masks use a white background, rectangular character boxes, and rectangular text boxes. Speech bubbles are solid blue, narration bubbles are blue with vertical black stripes, and shout bubbles are blue with horizontal black stripes.

Deploy:

```bash
cd /Users/guidotrevisan/Desktop/drawtoon/workflows/manga_caption
sam build
sam deploy \
  --stack-name drawtoon-manga-caption \
  --region us-east-1 \
  --profile lineart2-s3 \
  --capabilities CAPABILITY_IAM \
  --resolve-s3 \
  --parameter-overrides DatasetBucketName=drawtoon
```

Dry run:

```bash
python start.py \
  --stack-name drawtoon-manga-caption \
  --profile lineart2-s3 \
  --dry-run \
  --max-concurrency 400 \
  caption-pages \
  --caption-run haiku45_mangazero_panel_simple_v1 \
  --include-chapter-regex '_mangazero$'
```
