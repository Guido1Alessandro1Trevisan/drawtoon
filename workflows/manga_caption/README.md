# Drawtoon Manga Page Caption

This workflow captions filtered Drawtoon manga pages with Claude Haiku through Bedrock.

Canonical input:

```text
s3://drawtoon/datasets/pages/filtered/<chapter>/<page_side>.jpg
s3://drawtoon/datasets/annotations/magi_v3/<chapter>/<page_side>.jsonl
```

Canonical caption output:

```text
s3://drawtoon/captions/<caption_run>/<chapter>/<page_side>.json
```

The default model is:

```text
global.anthropic.claude-haiku-4-5-20251001-v1:0
```

## Architecture

The parent state machine is Standard and starts one Step Functions Distributed Map over chapter rows. Each map item is one chapter, and the child execution is also Standard because the chapter may contain hundreds of sequential page calls.

Inside a chapter child execution:

1. `InitializeChapter` loads the chapter page list and resumes from existing successful caption JSON if present.
2. `CaptionNextPage` captions exactly one page, writes `captions/<caption_run>/<chapter>/<page>.json`, updates compact chapter memory, and advances `next_page_index`.
3. The child loops back to `CaptionNextPage` until the chapter is complete.

This gives parallelism across chapters while keeping page order and memory deterministic inside each chapter.

Each caption is deterministically prefixed before it is stored:

```text
Black and White Manga. <title>. by <author>.
Colored Manga. <title>. by <author>.
```

The worker infers black-and-white versus color from the page image and reads title/mangaka metadata from `metadata/manga_metadata.json`, `metadata/manga_credits.json`, `manga_metadata.json`, or `manga_credits.json` if one exists in this workflow. You can also pass `--manga-metadata-json` with a workflow-relative JSON path or `s3://...` URI.

The worker uses the MAGI-v3 page annotation for layout grounding. It sends panel boxes, character boxes, text-region boxes, and compact prior memory to Bedrock, but it does not send OCR text content. The Bedrock call uses forced structured output, returning:

- one page-level caption
- one LAMIC CEI per panel
- LAMIC SADs for up to 5 characters and up to 7 speech/text bubbles per panel
- a memory update
- the compact memory to pass to the next page

LAMIC coordinates and sizes are attached by the worker from MAGI-v3, not generated by the model. Speech/text bubble SADs describe only the simple region type and do not include transcribed text. Stored text-bubble `type` values are normalized to `Speech Bubble`, `Thought Bubble`, `Narration Bubble`, `Shout Bubble`, `Text Bubble`, `Black Bubble`, or `Whisper Bubble`.

The chapter memory checkpoint is written away from canonical page records at:

```text
s3://drawtoon/captions/<caption_run>/_state/<chapter>/memory.json
```

Temporary job manifests, checkpoint state, and audit files are under `_jobs/`, `_state/`, and `_audit/` inside the caption run prefix.

## Deploy

```bash
cd /Users/guidotrevisan/Desktop/drawtoon/workflows/manga_caption
sam build
sam deploy \
  --stack-name drawtoon-manga-caption \
  --region us-east-1 \
  --profile lineart2-s3 \
  --capabilities CAPABILITY_IAM \
  --resolve-s3 \
  --parameter-overrides DatasetBucketName=drawtoon
```

## Dry Run Start Payload

This only prints the Step Functions input.

```bash
python start.py \
  --stack-name drawtoon-manga-caption \
  --profile lineart2-s3 \
  --dry-run \
  caption-pages \
  --caption-run haiku45_page_memory_v1
```

Remove `--dry-run` only when you want to launch the workflow.
